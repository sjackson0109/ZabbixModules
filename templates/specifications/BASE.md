# Base capability specification

The Base owner supplies local device identity, collection capability metadata and availability/uptime facts. It does not own peer resolution, frontend authorisation or vendor support inferred only from a marketing name.

Standard candidates: SNMPv2-MIB sysDescr `.1.3.6.1.2.1.1.1.0`, sysObjectID `.2.0`, sysUpTime `.3.0`, sysName `.5.0` and optional contact/location `.4.0`/`.6.0`. Use the exact numeric sysObjectID and documented model/firmware corroboration to select a qualified profile. Unrecognised values use a generic capability hypothesis with unknown support; no catch-all vendor-prefix claim. Device-reported sysName is source metadata and may repeat; it never renames the globally unique Zabbix host.

ENTITY-MIB candidates enrich chassis/member/slot, serial, manufacturer/model/firmware and parent relationships when exposed. A physical entry is not automatically a monitored interface: entAliasMappingIdentifier and vendor joins must be demonstrated. Preserve multiple stack/member identities instead of inventing a single chassis. LLDP local chassis subtype/ID provides useful peer identity when supported. Local management addresses come from authorised interface/IP/config evidence; do not copy a remote LLDP address into local identity.

Canonical `ne.device.snapshot` row contains hostname, nullable vendor/model/firmware, chassis_ids `{subtype,value}` list and management_addresses list. Its envelope is independently complete/failed/partial/unsupported. Observed time is not proxy delivery time; bound future skew and expose delivery age. A firmware or uptime discontinuity requests capability/identity re-evaluation; wrap and clock skew require distinct handling. sysUpTime often refers to agent subsystem uptime rather than chassis boot uptime, so label the fact accurately.

Proposed scalar availability/uptime owners use namespaced keys and avoid duplicating the current production alarm without an explicit migration decision. ICMP is optional and requires network reachability/proxy scope; SNMP poll failure is not equivalent to proven device power failure. Native item state/error plus last-success age must prevent stale normal snapshots from appearing healthy. Hardware health belongs to a separate qualified owner and cannot be silently discarded during a vendor rebuild.

Qualification inputs include exact sysObjectID/firmware/model/stack values, absent optional ENTITY/LLDP tables, denied SNMP view/auth failure, reboot/wrap, delayed proxy buffering, malformed/future timestamp and model changed after upgrade. Test source privacy, template linkage/key conflicts, version imports and inherited host context. Deliver profile evidence and unsupported reasons; no secret macros, raw credentials or global resolved peer metadata enter any snapshot.
