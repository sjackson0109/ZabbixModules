# Changelog

All notable changes are recorded here. Versions follow [Semantic Versioning](https://semver.org/); the current version is in [`VERSION`](VERSION).

## [Unreleased]

### Added
- Wi-Fi Explorer, Phase A ([roadmap](docs/wifi-explorer/ROADMAP.md)). A new optional frontend module, `wifiexplorer`, adds **Monitoring → Wi-Fi Explorer**: a site selector, overview (APs up, down, unknown and degraded; radios by band; channel utilisation per band; findings; data-source freshness), findings with evidence and next steps, AP inventory, AP and radio detail, and data quality. It reads through Network Explorer's permission-aware gateway, envelope validator and freshness rules, so a user sees only APs whose owner host they can read, and stale state is shown as unknown, never as up.
- `wifi-1.0` canonical schema (`schemas/wifi-envelope-1.0.schema.json`) with `device`, `ap_inventory`, `ap_state`, `radio_inventory` and `radio_state` datasets, and opaque AP and radio IDs derived from the AP MAC address.
- Native template `Wi-Fi Explorer - Aruba Instant VC by SNMP` for Zabbix 7.0, 7.2 and 7.4 (`templates/native/<version>/wifi_explorer_snmp.yaml`), generated by `templates/generate_wifi.py`. It reads AI-AP-MIB on the cluster's virtual controller, never guesses a radio band its channel does not prove, reports a member AP as unsupported, and carries no credential, API token or per-client item.
- Wi-Fi qualification: `qualify.py --product wifi` with its own [matrix](docs/qualification/WIFI_MATRIX.md) and evidence root, synthetic virtual-controller and member-AP evidence, and `capture_walk.py --profile aruba-instant`, which walks only the AI-AP-MIB objects Wi-Fi Explorer reads and sanitises AP names and serial numbers. Aruba Instant is Unqualified until sanitised real captures are added.
- A [review](docs/wifi-explorer/ARUBA_TEMPLATE_REVIEW.md) of an existing Aruba Instant template against the [Wi-Fi Explorer requirements](docs/wifi-explorer/REQUIREMENTS.md).
- Wi-Fi Explorer, Phases B–F ([design](docs/wifi-explorer/DESIGN.md#phases-bf-floors-rf-ssids-paths-impact-events-and-clients)):
  - **Configure** (Super admin): floors with optional plan images, AP placement by opaque AP ID, SSID intent (VLAN, where expected, bands), events and known BSSIDs, validated as one document and kept in the module configuration.
  - **Floor plans**: placed APs with status, band, channel, utilisation, client and neighbour overlays; shading between APs is labelled interpolation, never a survey; channel reuse backed by RF evidence.
  - **RF neighbours**: what each AP hears, from the new per-AP template `Wi-Fi Explorer - Aruba Instant AP by SNMP`, deduplicated by BSSID and bounded, classed from evidence while keeping the AP's own label; nothing is called malicious.
  - **SSIDs**: each cluster's SSIDs merged with declared intent; the VLAN is declared, never inferred, and per-AP broadcasting is labelled inferred.
  - Wired uplinks: each AP's switch port from switch-side LLDP and the AP's own LLDP, resolved with Network Explorer's identity rules (confirmed, one-sided, conflicting, ambiguous, unresolved).
  - **VLAN paths**: per SSID and AP, the declared VLAN checked port by port along the spanning-tree root ports to the root bridge, naming the first failing hop; stale, missing, disagreeing or MSTP-mapped evidence is never complete.
  - **Impact**: what a switch or port failure takes down (APs, SSIDs, VLANs, floors, clients now as an estimate), with LAG members and STP alternates considered.
  - **Events**: readiness checklists (SSID on air, APs up, VLAN paths, declared capacity, utilisation); credentials are listed as not checked.
  - **Clients**: one masked client snapshot per cluster (`{$WE.CLIENT.IDENTIFIERS}`: full, partial by default, or pseudonymised with the secret `{$WE.CLIENT.KEY}`), a search over what the policy kept, a trace to AP, radio, uplink and VLAN paths, and a sampled association timeline from snapshot history.
- `wifi-1.0` gains the `ssid`, `client` and `rf_neighbour` datasets.
- Wi-Fi Explorer, Phase G without hardware ([design](docs/wifi-explorer/DESIGN.md#phase-g-without-hardware-capacity-storage-rf-overlap-large-sites-section-36)):
  - **Capacity**: clients, the busiest AP, APs up and down and channel utilisation per band over the last day, month or year, from hourly trends of 13 new per-cluster `we.capacity.*` items (`{$WE.CAPACITY.HISTORY}`, `{$WE.CAPACITY.TRENDS}`). Hours without a complete observation are gaps, never zeros.
  - Storage: a complete attempt is stored as a receipt without its rows (`data_rows`, `data_omitted` in `wifi-1.0`), about halving what each dataset writes, and every dataset's history is a macro (`{$WE.<DATASET>.HISTORY}`).
  - `wifi_channel_overlap`: an inferred finding for a strong neighbour on a different channel whose spectrum overlaps, from the 802.11 channel plan.
  - Large sites: a configuration too large for plain storage is packed, so about 2,300 AP placements fit instead of about 750.
  - Browser checks of the Wi-Fi pages in Chromium (`tests/browser/wifi.lab.cjs`), run by the Compatibility workflow.

### Fixed
- Wi-Fi Explorer review fixes:
  - Saving the configuration under **Configure** (or moving an AP on a floor plan) no longer leaves a document that fails to load when SSID intent is declared: the editor's document is stored, not the normalised form with derived SSID IDs.
  - VLAN paths and impact no longer treat stale LLDP as current cabling: a stale AP uplink makes the path unknown (`uplink_stale`), and a root-port link seen only in stale LLDP stops the walk (`upstream_link_stale`).
  - A LAG member failure is *degraded* only when another member is up now; with stale member state it cannot be assessed. STP alternates count only with current state, and when a whole switch fails, an alternate that leads back to it is not offered as a reroute.
  - Event readiness: capacity is unknown, not failed, while APs of unknown state could still serve; "SSID enabled" looks only at the event's own site; utilisation is *not checked*, never passed, when no radio reports it.
  - A port blocked by spanning tree gets spanning-tree advice instead of "add the VLAN".
  - RF neighbours heard only in stale snapshots are listed as stale with when they were last seen and are no longer counted as heard now.
  - The overview reads the wired model for a site, so its findings include uplink and VLAN path findings and no longer change when an AP is selected.
  - Client snapshots without `{$WE.CLIENT.KEY}` carry a `client_key_missing` warning, shown on the Clients tab, because an unkeyed ID can be traced back to the MAC address.
  - The client timeline reads history a few values at a time and stops at its 16 MB bound instead of loading up to 73 snapshots first.

### Changed
- Network Explorer page: the topology starts higher. The per-dataset collection notices are one summary line that opens only when a source needs review, the root-bridge note is in the legend, zoom, fit and reset float over the canvas corner, and Focus and Expand LAG member links are secondary buttons.
- Network Explorer topology: a switch with findings shows a count badge coloured by its worst severity (Zabbix's Warning yellow, Information blue), and a switch with a stale or failed collection source gets a dashed outline and a "stale data" label; both are in the legend and the node's accessible name.
- Wi-Fi Explorer Overview: findings list AP and radio problems first within each severity, collection problems last, and one host's failed and stale datasets share one row with the datasets behind a disclosure. Findings, their IDs and the tile count are unchanged.
- Wi-Fi Explorer Capacity: the clients chart spans the page with a value axis, gridlines, time labels, direct line labels and a hover value per period; the busiest hour is a neutral line rather than red dashes, and the 24-hour view draws a single hourly line.
- Wi-Fi Explorer Capacity: periods with data for fewer than half their hours are marked "partial", and the 95th percentile and AP counts move to a second table behind a disclosure.
- Wi-Fi Explorer Impact: before a switch is chosen, the tab lists the switches on AP paths ranked by the APs that would lose service if each failed on its own, with degraded and possibly rerouted APs and clients on those APs now; each switch links to its full assessment.
- `DatasetQuality::describe()` and `EnvelopeValidator::envelope()` are now public Network Explorer services, shared with Wi-Fi Explorer; Network Explorer's behaviour is unchanged.

## [1.3.0] - 2026-10-11

### Added
- Monitoring → Network Explorer is now the network-wide view, with no global dashboard needed. With no parameters it draws every permitted switch as a Layer 2 topology; Site, Domain, Management subnet and Seed device narrow it; a View selector switches between Layer 2, Spanning Tree and VLAN; switches, links and link ends are selectable, with device, link and interface detail in one panel; findings, collection quality and CSV/JSON exports follow the same scope. The view, VLAN and selected interface are kept in the address.
- Site scope from the administrator-controlled `site` host tag, beside `ne.domain`. Selectors list only values on hosts the user can read.
- `NetworkScope` and `NetworkService::buildScope()`, one validated scope for the page, the JSON route, exports and widgets.

- Hardware qualification framework. [`docs/qualification/MATRIX.md`](docs/qualification/MATRIX.md) records, per vendor, model and firmware, one state for each capability (Interfaces, ENTITY, MAU, LLDP, VLAN, STP, LAG): Unqualified, Lab simulated, Captured-walk tested, Partially qualified, Real-device qualified or Unsupported, with known limitations and cited evidence. `tools/qualification/qualify.py` classifies a walk by replaying it through the native template normalisers, checks that evidence is sanitised (documentation addresses only, sanitiser placeholders, no credentials in the manifest), and fails CI when a state is not backed by cited evidence or the rendered matrix is stale. Every real vendor family starts Unqualified; only the synthetic lab profile is Lab simulated. The [evidence workflow](docs/qualification/README.md) supersedes the earlier `qualification_level` vocabulary.

### Changed
- The default branch is `main` instead of `work`; releases are cut from `main`.
- Explorer UX. A scope summary above the topology counts the drawn switches, links, LAGs, findings by severity, stale and failed datasets and unresolved neighbours (only permitted, returned objects). Find switch suggests visible switch names; Enter or Focus centres the view on a match and selects it, stepping through further matches, and dims rather than hides the others. In Spanning Tree, a selected switch offers Show path to root, which follows observed root ports to the agreed root, highlights the switches and links on the way, lists each root-port hop and says where and why the evidence stops. In VLAN, a selected switch offers Trace VLAN from this switch beside the existing source selector; a plain selection never changes the trace. The address now also keeps the selected switch (`selected_hostid`), the selected link (`link`, an opaque link ID checked by the server) and the trace source (`trace`).
- Fleet scaling. The 300-switch budget now limits only what one view draws; peers are resolved against up to 1,000 permitted Network Explorer hosts in the scope's domains. Site, domain and fleet scopes look up Network Explorer membership by exact item key before any budget applies, so a peer far down a large domain's host list still resolves and servers sharing a site or domain tag never use up the budget. Hosts that are not drawn are read for their device and LLDP snapshots only. The whole fleet counts only hosts with Network Explorer items, so servers no longer use up the budget. A scope that would draw more than 300 switches is not drawn: the page and widgets say how many devices it holds and ask for a narrower site, domain or seed device (the management subnet annotates rather than narrows); a filter matching more than 20,000 permitted hosts says its devices cannot all be identified, findings and quality are not claimed, and exports refuse it. A domain larger than the identity budget raises a warning finding instead of the old information-level truncation notice.
- Topology layout v2 (page and Topology widget). Network Explorer uses a deterministic, topology-aware hierarchical layout instead of a square grid. Layer 2 is arranged in levels from a deterministic anchor in each connected component, preferring the current agreed spanning-tree root; Spanning Tree uses observed root ports to form a root-oriented hierarchy, keeps switches without a root-port path, or with root ports towards different switches, in a labelled unresolved area, and falls back to the Layer 2 placement when no root is agreed. Physical cross-links, including blocked ones, stay visible and are never inferred from placement. Components are laid out apart, a few barycentre passes reduce crossings, and positions stay put through selection, search, VLAN, trace, LAG and refresh changes.
- The topology has Zoom in, Zoom out, Fit topology and Reset view buttons, keyboard alternatives (+, −, arrows, F, 0) and background drag to pan, all inside a bounded canvas that no longer widens the page. Links stop at switch boxes, external peers fan out around their switch, selection adds a second outline, link ends and interface rings that do not rely on colour, long names end in an ellipsis, and a compact legend lists only what the drawing shows.
- Pull-request CI runs the Chromium renderer suite, with Playwright locked in `tests/browser/package-lock.json`.
- Zabbix 7.0, 7.2 and 7.4 compatibility labs run nightly, on pull requests that change the frontend, widgets, templates, schemas or lab, and before every release; a release is published only when all three pass.
- Release archives and `manifest.json` carry a signed build-provenance attestation beside `SHA256SUMS` (`gh attestation verify`).
- Every third-party GitHub Action is pinned to a commit SHA, with a test that keeps it so.
- The default Layer 2 view (page and Topology widget) marks the observed spanning-tree root bridge when the visible switches in its domain agree on it and its data is current. A disagreement marks none and is explained.
- The Topology widget's link details make both endpoint interfaces selectable; selecting one shows its interface detail and broadcasts its item, so a linked Interface Detail widget follows. Its view labels are now Layer 2, Spanning Tree and VLAN.
- Documentation matches the implementation: build status, decisions, design pack, frontend architecture and test plan mark superseded passages, the release process states that published releases are immutable and that the next release is 1.3.0, and a [roadmap](docs/network-explorer/ROADMAP.md) records the improvement programme, the backlog and the boundary between the frozen schema 1.0 collector and a future acquisition agent.
- Dashboard recipes are optional examples, not installation steps. The lab acceptance walkthrough runs on Monitoring → Network Explorer; its old fleet dashboard is gone, and a test-only widget fixture checks the Topology widget.

## [1.2.0] - 2026-10-08

### Added
- A tag-driven release workflow: pushing `vX.Y.Z` verifies the version, runs CI, builds the packages and publishes a GitHub release with checksums. `scripts/release.py` bumps every component version and moves the changelog for a release; see [RELEASING.md](docs/operations/RELEASING.md).
- Continuous integration for the Python, Node and PHP checks, on PHP 8.0 and 8.3 and Python 3.10 and 3.12.
- A `templates` release package with the native standard-MIB templates, schemas and dashboard recipes.
- A single `VERSION` file, with a test that keeps every module manifest, the collector and the template normalisers in step.
- A Duktape compile check for every JavaScript step in the native and LAB templates.
- 25G, 40G and 100G media types in the MAU capability table.
- Validation of LAG member state and mode.
- An MIT `LICENSE`, shipped in every release package.
- Optional `warnings` in schema 1.1 envelopes, shown in the Data quality widget and as an informational finding.

### Changed
- Schema 1.1 moved from `schemas/proposed/` to `schemas/`; it is the current schema, and 1.0 is still accepted.
- The collector names the exception class on stderr when a collection fails unexpectedly, and checks timestamps without optional packages.
- Widgets show a message instead of reading data when the Network Explorer module is disabled; the menu entry appears only for users who can open the page.
- The widget runtime and stylesheet have one source in `src/widget/`; topology search dims nodes instead of redrawing, and SVG colours follow the dark theme.
- Every finding has the same fields and one stable ID scheme.
- A normaliser error now produces a failed envelope instead of no envelope.
- The LAB replay templates discard failed collections the same way as the native templates.
- The restart trigger ignores the 497-day `sysUpTime` wrap.
- Collector runtime dependencies are pinned by hash.
- The Python collector is a frozen fallback on schema 1.0.
- A duplicate interface name, a row missing its status columns or an `ifNumber` mismatch no longer makes the whole interfaces dataset partial. The row is skipped or keeps unknown fields, and the snapshot stays current.

### Fixed
- A VLAN row without an interface no longer attaches to LLDP links with an unmapped local port.
- The CSV formula guard also applies to text that is not valid UTF-8.
- A failed inventory read is no longer reported as stale inventory.

## 1.0.0 scope

The first production-capable release covers the specification's acceptance criteria:

- Physical interfaces with state, speed and reduced negotiated speed; port placement by stack member, slot and media; configurable state colours.
- LLDP peers, navigation from a local port to its remote peer, and remote interface highlighting.
- Multi-switch physical topology with a configurable management subnet that annotates, and never hides, connected devices outside it.
- VLAN membership with tagged and untagged distinction, and inter-switch VLAN propagation.
- STP state overlay, and LAG members shown as one logical connection.
- Native Zabbix SNMP templates on standard MIBs for Zabbix 7.0, 7.2 and 7.4, plus an optional Python collector, all feeding one canonical model.
- Zabbix user permissions respected on every read, and collection failures and stale data shown distinctly.
